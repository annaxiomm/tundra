# styleguide
this is just personal reference so I can stay consistent

## Commits
- commits should be individual (meaning ONE change per commit)
- no "changed some things" or "updated visuals" - commits must be descriptive
- if you make multiple changes in one session, break it into smaller commits
  - if this isn't possible, apologise profusely to your future self
- all commits should be prefixes with one of the pre-determined commit types

### Types of Commits
- fix - when something breaks and you fix it
- feature - when you add something
- update - when you make a minor update to something
- cosmetic - when you change the appearence of something
- meta - when you add something that's not directly related to the product (like this!)
- if you add a new commit type, add it here
